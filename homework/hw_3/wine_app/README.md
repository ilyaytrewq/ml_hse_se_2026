# Wine Quality — приложение сомелье (ДЗ-3, часть 4)

Streamlit-приложение, которое показывает, как работает итоговая модель ДЗ-3
(log1p-преобразование → StandardScaler → полиномиальные взаимодействия 2-й степени → отбор по весам L1 (SelectFromModel) → логистическая регрессия с L1-регуляризацией, без весов) и как выбор порога влияет на подборку.

**Модель внутри приложения не обучается** — загружаются артефакты ноутбука:

| Файл | Что это |
| --- | --- |
| `app.py` | код приложения |
| `model.joblib` | итоговый пайплайн (log1p + StandardScaler + полиномиальные взаимодействия + SelectFromModel + LogisticRegression), обученный на train |
| `config.json` | порог, подобранный на валидации (t_R: макс. precision при recall ≥ 0.7) |
| `test.csv` | тестовая выборка (12 признаков + target) |
| `requirements.txt` | версии библиотек, при которых приложение проверено |

## Локальный запуск

Проверено на **Python 3.14.7** (версии библиотек зафиксированы в `requirements.txt`).

```bash
python3.14 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/streamlit run app.py
# откройте http://localhost:8501
```

Windows:

```bat
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\streamlit run app.py
```

## Что внутри (задания 4.1–4.5)

- **«Одно вино»** — ввод 12 признаков (мин/макс и значение по умолчанию — из `test.csv`;
  `is_red` — переключатель «красное/белое»); в сайдбаре ползунок порога (по умолчанию — из `config.json`).
- **«Модельные метрики»** — матрица ошибок, precision/recall/F1 и ROC/PR-кривые с отметкой
  текущего порога; подсказка сомелье, что произойдёт при изменении порога.
- **«Пакетное предсказание»** — CSV с признаками; если столбцов не хватает — понятное сообщение
  (`st.error`); результат можно скачать.
- **«Что выучила модель»** — горизонтальная диаграмма коэффициентов (после преобразований пайплайна).

## 4.5. Почему `st.cache_resource` для модели и `st.cache_data` для таблиц

- Модель — один «ресурс»: тяжёлый неизменяемый объект, общий для всех. `st.cache_resource`
  создаёт её один раз на процесс и не пытается хешировать/копировать содержимое.
- Тестовая таблица и предвычисленные вероятности — данные: `st.cache_data` кэширует результат
  по хешу аргументов и при повторном вызове с теми же аргументами возвращает копию. Вероятности
  считаются один раз в функции с `st.cache_data`; при движении слайдера порога меняется только
  сравнение с порогом, `predict_proba` заново не вызывается (аргумент-модель помечен `_model`,
  чтобы не участвовать в хеше).
- Без декоратора `joblib.load` выполнялся бы при каждом действии пользователя (каждый сдвиг
  слайдера заново прогоняет `app.py` сверху вниз) — модель читалась бы с диска десятки раз.
